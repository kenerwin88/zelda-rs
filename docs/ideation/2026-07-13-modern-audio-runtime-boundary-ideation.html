Ideation: The Next Modern Audio Improvement

The modern renderer is now waveform-exact, engine-driven, portable across build modes, and protected by generated route-independent conformance. This pass asks what single architectural move creates the most leverage from that foundation.

Evidence before ideas

Grounding Context

Codebase Context. Production NMI code now emits typed EngineAudioCommand values. Modern-only builds exclude the legacy SpcPlayer; modern samples and catalogs are owned assets; portable snapshots and a 256-case shrinking command generator protect deterministic continuation. The full 1,073,092-frame standard route is sample-exact against the DSP-compatible oracle.

The remaining seam is duplicated representation. audio.rs still pushes a hardware-shaped ModernApuState.pending_write into a 16-entry history. The v5 compact snapshot serializes that ModernApuState, then restore calls rehydrate_commands_from_ports(). Modern NMI acknowledgement also still reads a raw APUI output byte. The typed command model exists, but raw legacy transport state remains authoritative in several production transitions.

External Context. Rust’s standard library describes channels as ordered message communication with bounded and unbounded variants. That validates the command-transport separation, but this project’s queue must remain deterministic and serializable, so a small owned fixed-capacity queue is a better fit than a threaded standard channel.

The cut

Ranked Ideas

1Extract a typed ModernAudioRuntime with a one-way legacy gateway

Create one modern-owned runtime containing the typed 16-entry command-batch queue, sequencer, renderer, sample-bank selection, semantic acknowledgements, and compact snapshot state. Production gameplay and modern snapshots would never store or reconstruct APUI bytes. Old snapshots, DSP tracing, and the oracle would decode legacy ports only inside a compatibility adapter.

Axis
Command transport and source of truth
Basis
direct: audio.rs still queues pending_write; v5 snapshots own ModernApuState; restore invokes rehydrate_commands_from_ports(); modern NMI behavior still reads a raw APUI acknowledgement.
Rationale
This removes the last duplicated source of truth. The modern path becomes an independent subsystem rather than a modern renderer behind a legacy transport. It also makes future MSU unification, named sound IDs, modding, performance gates, and alternate hosts cheaper.
Downsides
Large migration surface. It must preserve last-write-wins latches, 16-entry overflow behavior, acknowledgement semantics, MSU interaction, v1-v5 snapshot migration, and every current parity gate.
